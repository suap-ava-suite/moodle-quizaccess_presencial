# Não criar uma interface própria de auditoria

O plugin emitirá eventos Moodle para todas as ações auditáveis, mas não oferecerá telas próprias para consultar esses eventos. Professores e auditores utilizarão os mecanismos de log e relatórios já disponíveis na instalação, e a duração do histórico seguirá a retenção configurada para o armazenamento de logs. Essa escolha evita duplicar dados e controles de acesso, aceitando que a experiência e o tempo disponível de consulta dependam da configuração institucional do Moodle.
